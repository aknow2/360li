# Feature Specification: Non-2:1 Image Support (2:1 Padding)

**Feature Branch**: `002-aspect-padding`  
**Created**: 2025-12-16  
**Status**: Draft  
**Input**: User description: "360度画像以外に対応したいです。画像を読み込んだ時2対1でない場合は、2対1になるように画像を拡張します。拡張した部分は白色とします。また画像の縮小率を指定して余白部分を調整できるようにしたい"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Non-2:1 image can be used (Priority: P1)

ユーザーとして、2:1のエクイレクタングラー画像でなくても画像を読み込み、アプリ側で2:1の作業用画像に変換（白余白で拡張）して、これまで通りに3D生成・プレビュー・STL出力まで進めたい。

**Why this priority**: 現実の入力画像は常に2:1とは限らず、入力制約が強いと利用できる画像が限定されるため。

**Independent Test**: 2:1ではない画像を1枚アップロードし、Buildボタンで3D生成できれば達成。

**Acceptance Scenarios**:

1. **Given** 2:1ではないJPEG/PNG画像がある, **When** ユーザーが画像を選択する, **Then** アプリはエラーにせず、内部で2:1の作業用画像に変換して次の操作（Build）が可能になる
2. **Given** 2:1ではない画像が読み込まれている, **When** ユーザーがBuildを押す, **Then** 生成結果（3Dプレビュー/STL）が作業用画像に基づいて作られる
3. **Given** 2:1画像が読み込まれている, **When** ユーザーがBuildを押す, **Then** 追加の拡張（白余白追加）を必須とせず生成できる

---

### User Story 2 - Adjust padding by scale (Priority: P2)

ユーザーとして、画像の縮小率（スケール）を指定して、白余白の量を調整し、意図した範囲が球面に配置されるようにしたい。

**Why this priority**: 余白調整によって、縁が切れる・写したくない領域が目立つ等を回避でき、仕上がりのコントロールがしやすくなる。

**Independent Test**: スケールを変えてBuildを押し、出力の凹凸が変化することを確認できれば達成。

**Acceptance Scenarios**:

1. **Given** 画像が読み込まれている, **When** ユーザーが縮小率を変更してBuildを押す, **Then** 出力される凹凸（厚み分布）が変更後の縮小率に応じて変化する
2. **Given** 画像が読み込まれている, **When** 縮小率を小さくする, **Then** 白余白が増える（画像がキャンバス中央に小さく配置される）

---

### User Story 3 - Orientation is preserved (Priority: P3)

ユーザーとして、入力画像の向き（上下左右）が意図せず反転しないことを確認したい。

**Why this priority**: 反転は出力の意味が変わるため（地形/文字/人物など）品質上の致命的問題になりやすい。

**Independent Test**: 方向が分かるテスト画像（例: 左上に文字/マーカー）でBuildし、プレビューのテクスチャと凹凸の配置が一致することを確認できれば達成。

**Acceptance Scenarios**:

1. **Given** 方向が分かるテスト画像がある, **When** 画像を読み込んでBuildする, **Then** 上下左右が反転せずに反映される

---

### Edge Cases
- 入力が極端に縦長/横長でも、白余白の追加によって必ず2:1の作業用画像が作成され、Buildできる
- 縮小率が極端に小さい場合でも、アプリはクラッシュせず、生成結果が「ほぼ白（凹凸がほとんど無い）」として扱える
- 入力画像が非常に大きい場合でも、ユーザー操作ができなくなるほど長時間フリーズしない（必要に応じてユーザーに注意/エラーを提示できる）
- 透過PNGを入力した場合、透過部分は白として扱われる

## Requirements *(mandatory)*

### Functional Requirements


- **FR-001**: システムは、2:1以外の画像（JPEG/PNG）を読み込めること
- **FR-002**: システムは、入力画像の縦横比が2:1でない場合、**白色**の余白で拡張して2:1の作業用画像を作ること（元画像は引き伸ばさない）
- **FR-003**: システムは、作業用画像を作る際に、ユーザーが指定した縮小率（スケール）に基づいて元画像を縮小してから、2:1の作業用画像の中央に配置すること（左右・上下は均等）
- **FR-004**: システムは、縮小率（スケール）として「0より大きく、1以下」の値を受け付けること。範囲外（0以下/1より大きい）の場合、Buildを実行せず、ユーザーに分かる形でエラーを提示すること
- **FR-005**: システムは、生成（Build）時に「作業用画像」を使用して凹凸（厚み）を計算すること（プレビュー用の見た目だけでなくSTLの形状に反映されること）
- **FR-006**: システムは、プレビュー表示用のテクスチャを表示する場合、凹凸と同じ向き・同じ作業用画像に基づいて表示すること（上下左右の不一致が起きないこと）
- **FR-007**: システムは、2:1画像を入力した場合でも、縮小率の指定によって白余白を追加できること
- **FR-008**: システムは、入力が2:1かつ縮小率が1.0の場合、作業用画像は入力画像と同一の見た目になること（余白追加や拡大縮小が発生しない）

### Assumptions

- 縮小率（スケール）のデフォルトは 1.0 とする
- 余白は常に白とし、透過PNGは白背景として扱う
- 元画像は中央配置（左右・上下は均等）とする

### Key Entities *(include if feature involves data)*

- **Input Image**: ユーザーがアップロードする元画像（任意の縦横比）
- **Working Image (2:1)**: 生成に使用する2:1の作業用画像（白余白＋縮小率反映済み）
- **Image Transform Settings**: 縮小率（スケール）、余白色（白固定）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 2:1でない画像を含む少なくとも10枚の代表的な入力（縦長/横長/正方形を含む）で、エラー無くBuild→3Dプレビュー→STL出力まで完了できる
- **SC-002**: 同一の入力画像で、少なくとも2つの異なる縮小率（例: 1.0 と 0.7）でBuildした結果において、凹凸（厚み分布）の違いがユーザーに視認できる
- **SC-003**: 方向が分かるテスト画像で、プレビューのテクスチャと凹凸の配置が一致し、上下左右の反転が発生しない
- **SC-004**: 2:1でない画像をアップロードしてもエラーでブロックされず、Build→3Dプレビュー→STL出力まで完了できる
