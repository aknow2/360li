# Implementation Tasks: Split Preview / STL Export

## Operating rules

- All implementation checkboxes below start unchecked. The orchestrator—not the worker—marks a task complete and creates its separate commit only after independent review.
- Work strictly in Phase 0 through Phase 8 order. Do not begin a later phase while its prerequisite phase is unreviewed.
- TDD means: add the named test first, run the focused command and observe its stated red failure, implement one focused unit, then run the focused command green and the phase quality gate.
- `TEST_MODULE` is interpreted by the dependency-free Vite/Node runner introduced in Phase 0. No package or lockfile dependency changes are permitted. `tsconfig.json` and the root project-reference graph are immutable.
- `e2e-test.md` is a subsequent, separately approved artifact. The next E2E-spec prompt creates its immutable scenario definitions and an execution-record table for every stable scenario. This task round does not create or edit it; after implementation, only the orchestrator may update its result/evidence fields as T8.2 specifies.
